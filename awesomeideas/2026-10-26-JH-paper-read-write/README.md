# 从文献调研到 Related Work：用 AI Skills 保住证据链

| 项 | 内容 |
| :--- | :--- |
| 分享人 | 江涵 |
| 日期 | 2026-10-26 |
| 工具 | Codex + 已安装的科研 Skills |
| 适用场景 | 选定调研问题、系统查阅论文、写论文的 Related Work |

## 一句话结论

按**确定问题 → 检索 → 筛选 → 精读 → 跨论文比较 → 证据综合 → 写 Related Work → 核验**推进。每一步留下能交给下一步的材料，最后得到有来源支撑的相关工作正文。

## 场景

准备论文的 Related Work 时，直接让 AI “搜论文并写一段”，容易漏掉相反证据，把不同设定的结果放在一起比较，甚至引用只看标题、没有核对原文。更稳妥的办法是把调研过程拆成可追溯的阶段。

我在 Codex 中安装了 [nature-skills](https://github.com/Yuan1z0825/nature-skills)、[Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills) 以及文献对比技能 `literature-triage-matrix`。下面分享的是将它们串成调研流程的**使用方法和原创提示词**。没有安装技能时，也可以按交付要求使用提示词；让 AI 如实说明它实际完成了哪些检索与核验。

## 做法

先告诉 AI：**我的具体研究问题、任务设定、希望覆盖的时间范围、目标读者/会议、自己方法与已有工作的区别**。如果这些还不清楚，先做问题界定，不急着写正文。

| 阶段 | 主用 Skill | 这一步要交付什么 |
| :--- | :--- | :--- |
| 1. 确定调研问题 | `deep-research` | 2～3 个可回答的研究问题、检索关键词组、纳入/排除标准；已有论文清单也可作为起点 |
| 2. 检索与核实条目 | `nature-academic-search` | 检索式、检索日期与来源、候选论文清单；每条至少核对标题、作者、年份和 DOI/正式链接 |
| 3. 获取可读原文 | `nature-downloader` | 开放获取或本人有权限访问的全文与补充材料；拿不到全文的条目标记“仅摘要/元数据” |
| 4. 初筛与精读 | `nature-paper-card` | 纳入论文及排除理由；核心论文逐篇记录问题、设定、方法、实验、主要主张、原文证据位置和局限 |
| 5. 横向比较 | `literature-triage-matrix` | 按相同维度比较已知论文：任务设定、数据、方法、评价指标、结论、局限和与自己工作的关系 |
| 6. 综合调研 | `deep-research` | 按研究路线或问题组织的调研结论：共识、分歧、证据不足之处，以及对研究问题的逐项回答 |
| 7. 写 Related Work | `paper-writer` | 先做“论断—来源”清单，再写按主题组织的正文；每段说明一组工作解决了什么、留下什么问题、与本文有什么关系 |
| 8. 核验与润色 | `nature-ref-verifier`、`paper-polish` | 核对书目字段和 DOI，逐句回原文核对论断与引文的支撑关系，最后做不改变含义的语言润色 |

**按需加的 Skill：**需要逐段中英对照、查看图表公式时用 `nature-reader`；长期追踪固定方向时用 `nature-literature-pipeline` 做周期性发现和初筛；仅在专门找 Nature/Science/Cell 系列证据时用 `nature-citation`；如果写的是综述论文而非普通论文的 Related Work，可把第 7 步改为 `nature-writing`。这些是分支，不需要每次全跑。

这里有两个容易混淆的检查：`nature-ref-verifier` 主要核对**书目字段**；“这篇文献是否真的支持这句话”还要回到论文原文、精读卡和证据位置逐条判断。

### 提示词

把方括号中的内容换成自己的材料。第一次调研可以没有论文列表，从研究问题和检索开始；已收集论文时把 PDF/DOI 一起交给 AI。

```text
我要完成[具体研究问题/方向]的文献调研，并写一节论文 Related Work。
我的研究设定与方法是[简述]；希望覆盖[时间范围、学科、目标会议或期刊]。
已有论文/材料：[PDF、DOI、BibTeX 或“暂无，请从检索开始”]。

请按下面的阶段推进，使用当前环境中确实已安装的 Skills：
1. 用 deep-research 界定 2～3 个可回答的调研问题，列出检索关键词、纳入/排除标准和可能遗漏的相邻方向。
2. 用 nature-academic-search 检索。记录检索式、来源、日期和候选论文；核实标题、作者、年份、DOI/正式链接。不要只凭搜索摘要判断方法与实验结果。
3. 对核心论文，用 nature-downloader 寻找开放获取或我有权限访问的全文；拿不到的标记“仅摘要/元数据”，不要假装精读过。
4. 根据研究问题筛选论文并解释排除理由；用 nature-paper-card 精读纳入的核心论文，记录主张、方法、关键实验、证据页码/图表和局限。
5. 用 literature-triage-matrix 对已知论文做横向比较。按任务设定、数据、方法、评价指标、主要发现和局限对齐；相近工作需指出真正不同的轴。
6. 用 deep-research 综合共识、分歧与证据空白，逐项回答第 1 步的调研问题。区分“论文报告的结论”“跨论文推断”“尚未验证的猜想”。
7. 先列“准备写入 Related Work 的论断—来源—证据位置”清单，再用 paper-writer 写按研究路线组织的正文。避免逐篇摘要堆砌；不要编造引文、数字或我的实验结果。
8. 用 nature-ref-verifier 核对参考文献的书目字段和 DOI；再对照原文检查每条引文是否支撑相邻论断。最后用 paper-polish 润色，不改变科学含义。

交付：调研问题与检索记录、纳入/排除清单、核心论文精读卡、跨论文矩阵、调研综合结论、Related Work 正文、参考文献、待我核实的问题。
如果材料或工具不足，请标明证据边界，继续完成能可靠完成的部分；不要声称做过实际未做的检索、全文阅读或核验。
```

## 效果

下面比较的是**提问方式和交付要求**，不是论文质量的实测跑分：

| 对比项 | 原始问法：“搜点论文，帮我写相关工作” | 上述 Skill 工作流 |
| :--- | :--- | :--- |
| 检索覆盖 | 没有检索范围与记录 | 明确研究问题、检索式、时间范围及纳入/排除理由 |
| 阅读依据 | 未要求指出原文位置 | 精读卡标注页码、图表或“仅据摘要” |
| 文献关系 | 容易形成逐篇摘要列表 | 同一维度的跨论文对比矩阵，按研究路线综合 |
| 正文来源 | 未区分论文结论与模型推断 | 先列“论断—来源—证据位置”，再写 Related Work |
| 引文检查 | 未要求核对书目或论断支撑 | 分别核对书目字段与原文支撑关系 |

以提示词中明确写出的可检查要求计，原始问法是 **0 类**，新问法至少有 **5 类**：检索记录、原文定位、跨论文比较、论断溯源、引文核对。这个数字只比较提示词约束；实际质量还要看检索覆盖、全文材料和人工复核。

## 踩坑

1. 只有标题或摘要时，不能据此写方法细节、消融结果或机制解释；补全文或把论断限定为摘要能支持的范围。
2. 检索到很多篇不等于覆盖充分。要记录检索式与排除理由，并检查相反观点、相邻领域和较新的工作。
3. “参考文献格式正确”不等于“引文支持这句话”。`nature-ref-verifier` 核对书目，论断支撑还需看原文。
4. `nature-literature-pipeline` 适合长期自动跟踪；一次性的 Related Work 不需要为了“流程完整”而配置定时推送。
5. Skill 是工作流程说明，不能替代检索工具、全文访问和人的学术判断。公开分享时不要附上未公开的论文草稿、实验数据或带个人信息的截图。

## 复用建议

- 已有一组论文时，可以从“精读 → 横向比较”开始；从零摸方向时，先做“确定问题 → 检索 → 筛选”。
- 中间产物留在本地项目里：检索记录、精读卡、对比矩阵和论断—证据清单。补文献或修改 Related Work 时，直接从对应阶段继续。
